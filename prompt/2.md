## 1. Guía de Configuración de Firebase en Plan Gratuito (Plan Spark)

El **Plan Spark** de Firebase es completamente gratuito y **no requiere tarjeta de crédito**. Al combinarlo con el despliegue de la aplicación estática en **GitHub Pages**, obtienes una infraestructura de costo $0 USD capaz de soportar cientos de miles de visitas al mes sin costo de hosting.

### Paso 1: Creación del Proyecto en Firebase Console
1. Ingresa a [Firebase Console](https://console.firebase.google.com/) con tu cuenta de Google.
2. Haz clic en **"Agregar proyecto"** (o "Crear un proyecto").
3. Asigna un nombre (ej: `invitaciones-saas-prod`).
4. En el paso de Google Analytics, puedes activarlo o desactivarlo según prefieras (desactivarlo agiliza la configuración inicial).
5. Haz clic en **"Crear proyecto"**.

### Paso 2: Registrar la Aplicación Web y Obtener Credenciales
1. En el panel principal del proyecto, haz clic en el ícono Web `</>` para registrar una aplicación.
2. Nómbrala `invitaciones-web`.
3. **No** marques la casilla de "Firebase Hosting" (ya que usaremos GitHub Pages para el frontend).
4. Copia el objeto `firebaseConfig` que te entrega la consola.
5. Crea un archivo `.env` en la raíz de tu proyecto local basándote en `.env.example`:
   ```env
   VITE_FIREBASE_API_KEY=AIzaSy...
   VITE_FIREBASE_AUTH_DOMAIN=invitaciones-saas-prod.firebaseapp.com
   VITE_FIREBASE_PROJECT_ID=invitaciones-saas-prod
   VITE_FIREBASE_STORAGE_BUCKET=invitaciones-saas-prod.appspot.com
   VITE_FIREBASE_MESSAGING_SENDER_ID=1234567890
   VITE_FIREBASE_APP_ID=1:1234567890:web:...
   VITE_BASE_PATH=/
   ```

### Paso 3: Configurar Firebase Authentication
1. En el menú lateral izquierdo, ve a **Compilación > Authentication** y haz clic en **"Comenzar"**.
2. En la pestaña **"Sign-in method"**, activa los proveedores requeridos:
   - **Correo electrónico/Contraseña:** Habilita el primer interruptor (Email/Password).
   - **Google:** Habilita Google y selecciona tu correo de soporte.
3. En la pestaña **"Configuración" > "Dominios autorizados"**:
   - Por defecto ya están `localhost` y tu dominio de Firebase.
   - Haz clic en **"Agregar dominio"** y agrega el dominio de GitHub Pages donde vivirá tu aplicación (ej: `tu-usuario.github.io`).

### Paso 4: Configurar Cloud Firestore
1. En el menú lateral, ve a **Compilación > Firestore Database** y haz clic en **"Crear base de datos"**.
2. **Ubicación:** Selecciona la región geográfica más cercana a tus clientes (ej: `us-central1` o `nam5`). *Nota: La ubicación no se puede cambiar después*.
3. **Reglas de seguridad:** Inicia en **"Modo de prueba"** durante el desarrollo, o aplica directamente las reglas seguras en la pestaña **"Reglas"**:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Invitaciones: Lectura pública (los invitados deben verla sin login)
    // Creación y edición: solo el usuario autenticado propietario
    match /invitaciones/{invitationId} {
      allow read: if true;
      allow create: if request.auth != null;
      allow update, delete: if request.auth != null && resource.data.userId == request.auth.uid;
    }
    
    // Confirmaciones RSVP: Cualquier invitado puede enviar su respuesta
    // Lectura: solo el dueño del evento autenticado
    match /confirmaciones_rsvp/{rsvpId} {
      allow create: if true;
      allow read: if request.auth != null;
      allow update, delete: if request.auth != null;
    }
    
    // Catálogo de Servicios: Lectura pública
    match /servicios/{servicioId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    
    // Perfiles de Usuario: Cada usuario administra su propio documento
    match /usuarios/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

### Paso 5: Configurar Cloud Storage (Incluido en el Plan Gratuito)
1. En el menú lateral, ve a **Compilación > Storage** y haz clic en **"Comenzar"**.
2. Selecciona la misma ubicación geográfica de tu base de datos.
3. En la pestaña **"Reglas"**, define las reglas que permitan ver las fotos públicamente y subir solo a usuarios autenticados con límite de peso:

```javascript
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /invitaciones/{allPaths=**} {
      // Lectura pública de fotos de la invitación
      allow read: if true;
      // Subida: solo usuarios autenticados y archivos menores a 10 MB
      allow write: if request.auth != null 
                   && request.resource.size < 10 * 1024 * 1024
                   && request.resource.contentType.matches('image/.*');
    }
  }
}
```

## 2. ¿Es Conveniente Firestore para la Administración de Imágenes?

### Dictamen del Arquitecto
> **Respuesta:** **NO es conveniente almacenar imágenes binarias o Base64 directamente dentro de documentos de Firestore en producción.** 
> La arquitectura recomendada y estándar es: **Firebase Storage para los archivos binarios + Firestore para la metadata y URLs públicas**.

### Motivos Técnicos:

1. **Límite Estricto de 1 MB por Documento en Firestore:**
   - En Firestore, el tamaño máximo absoluto de un documento (incluyendo todos sus campos y arrays) es de **1 MiB (1,048,576 bytes)**.
   - Una foto tomada con un smartphone actual pesa entre 3 MB y 12 MB. Al codificarla a Base64, el tamaño se infla en un **33% adicional**. Intentar guardar una sola imagen sin comprimir en Firestore provocará un error de base de datos irrecuperable (`Document size exceeds limit`).

2. **Degradación de Rendimiento y Consumo Excesivo de Ancho de Banda:**
   - Cuando un invitado abre una invitación (`/invitacion/j-m-2024`), Firestore descarga **el documento entero**.
   - Si ese documento contiene 4 o 5 imágenes en Base64 que pesan 800 KB, el teléfono del invitado tardará segundos en descargar el JSON, ralentizando la apertura en redes 3G/4G móviles.

3. **Inexistencia de CDN Multimedia y Caché HTTP:**
   - Firestore entrega datos vía WebSocket/gRPC. No cuenta con encabezados de caché HTTP (`Cache-Control: public, max-age=31536000`), mientras que **Cloud Storage sí cuenta con CDN global**, lo que permite que una imagen se descargue instantáneamente desde la caché del navegador de los invitados sin volver a consultar el servidor.

---

### ¿Cuándo sí se puede usar Firestore para Imágenes? (Ajuste Realizado)

Si por simplicidad o decisión de arquitectura se desea centralizar todo en Firestore sin activar Cloud Storage, **SÍ es viable siempre y cuando se aplique una estricta compresión en el cliente (Browser HTML5 Canvas a formato WebP)** para asegurar que cada imagen pese **menos de 150 KB - 250 KB**.

### Ajustes Implementados en el Código del Proyecto

Para darte máxima flexibilidad, se han implementado **ambas opciones de forma híbrida y configurable** en el proyecto:

#### 1. Servicio de Compresión y Almacenamiento (`src/core/services/storageService.js`)
- **Compresión automática en el navegador:** Utiliza la API Canvas para redimensionar la imagen a dimensiones web (máx. 1200px) y convertirla a formato **WebP** con calidad 0.8. Una foto de 4.5 MB se reduce a ~120 KB antes de cualquier subida (reducción del 95%).
- **Método `uploadToStorage(file, folderPath)`:** Sube la imagen comprimida a Firebase Storage y retorna la URL pública HTTPS con caché de 1 año.
- **Método `saveImageToFirestore(invitationDocId, file, caption)`:** Si se elige el modo Firestore, comprime la imagen a WebP estricto (< 250 KB) y la anexa al array `gallery` del documento en Firestore usando `arrayUnion`.

#### 2. Componente de Subida Visual (`src/features/builder/components/ImageUploader/`)
- Muestra el porcentaje de reducción en tiempo real (ej: *Reducción del 96% de 3.8 MB a 145 KB*).
- Permite seleccionar entre modo **Firebase Storage** (Recomendado) o **Firestore** (Base64 comprimido).

#### 3. Integración en el Builder (`src/features/builder/pages/BuilderPage.jsx`)
- Selector de motor de almacenamiento (Storage vs Firestore).
- Subida interactiva para la foto de portada (Hero Image) y fotos de la galería de recuerdos.

## 3. Guía de Uso de la Administración de Imágenes

### Opción A: Usando Firebase Cloud Storage (Recomendada)
1. Activa Cloud Storage en Firebase Console (ver Paso 5 de la guía).
2. En el Builder, selecciona **"Firebase Storage (Recomendado)"**.
3. Sube la foto: el cliente la comprimirá a WebP, la subirá a `invitaciones/` y almacenará únicamente la URL HTTPS en Firestore.

### Opción B: Usando Firestore Directamente (Base64 WebP)
1. No requiere configurar Cloud Storage en Firebase Console.
2. En el Builder, selecciona **"Firestore (Base64 optimizado)"**.
3. Sube la foto: el algoritmo de `storageService.js` validará que la imagen comprimida no exceda los 350 KB y la guardará directamente en el documento de Firestore. Se sugiere limitar la galería a un máximo de 3 a 5 fotografías para no saturar el límite de 1 MB del documento.
