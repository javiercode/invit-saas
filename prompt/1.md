Actúa como un Arquitecto de Software Full-Stack experto en React (Vite), Firebase y metodologías de Arquitectura Limpia. Tu objetivo es diseñar y generar la estructura de código para una plataforma SaaS de creación de invitaciones digitales interactivas y responsivas.

El proyecto se desplegará en GitHub Pages (o similar) y utilizará Firebase (Firestore, Auth y Storage) como Backend-as-a-Service. Creando skills de las siguientes normas

Debes seguir estrictamente las siguientes directrices de arquitectura, diseño y funcionalidad:

1. ARQUITECTURA DE DIRECTORIOS (Limpia y Ordenada)
Estructura el proyecto de forma modular. Cada componente debe residir en su propia carpeta con su archivo de lógica/JSX, estilos y componentes hijos inmediatos. Agrupa los componentes por módulos/menús del negocio. Sigue este esquema de ejemplo:

├── features/         # Módulos principales del negocio (Agrupados por Menús)

│   │   ├── components/CardCatalogo/, GridServicios/
│   │   └── pages/CatalogPage.jsx
│   ├── dashboard/    # Menú de usuario / administración de invitaciones
│   └── builder/      # Constructor y Editor de invitaciones mediante plantillas
└── templates/        # Motor de plantillas HTML/React dinámicas (Boho, Clásico, Moderno)

2. REQUISITOS DEL CATÁLOGO DE SERVICIOS
- Inspirado en la estética limpia, minimalista y visual de Canva (Referencia: tu-invitación-ideal.my.canva.site/catalogobodas).
- Diseño 100% Mobile-First (Responsivo en celulares, ya que el 90% de los usuarios finales visualizan invitaciones en móviles).
- Sistema de filtros por tipo de evento, precios y estilos.

3. MOTOR DE INVITACIONES Y PLANTILLAS PERSONALIZADAS
- El sistema debe generar invitaciones interactivas como la referencia (clic-estudio-creativo-ag.my.canva.site/j-m-2024) pero renderizadas dinámicamente mediante plantillas estructuradas en código (no embebidas de Canva).
- Características obligatorias por invitación: Cuenta regresiva, mapa interactivo (Google Maps/Waze), botón de confirmación de asistencia (RSVP conectado a Firestore), galería de fotos, e información de la mesa de regalos.
- El builder debe permitir inyectar un JSON de datos (nombres, fecha, locación, fotos) en múltiples plantillas HTML/React intercambiables (Mínimo define la estructura para 3 tipos: Elegante, Vintage, Moderna).

4. INTEGRACIÓN CON FIREBASE
- Autenticación: Registro e inicio de sesión de clientes.
- Firestore: Estructura colecciones para `usuarios`, `servicios` e `invitaciones` (guardando el JSON de datos seleccionado y el ID de la plantilla elegida).
- Storage: Almacenamiento de las fotos de los novios/festejados.

ENTREGABLE REQUERIDO:
1. Genera el árbol completo de directorios optimizado para este negocio.
2. Proporciona el archivo de configuración de Firebase (`core/firebase.js`).
3. Proporciona el código de la estructura base del renderizador de plantillas dinámicas (`features/builder/TemplateRenderer.jsx`) que reciba los datos de Firestore y pinte la plantilla HTML responsiva seleccionada.
4. Explica brevemente la estrategia para que las rutas de GitHub Pages no rompan el enrutamiento de React Router al acceder a una invitación (ej: /invitacion/boda-juan-y-maria).

### Entregable 3: Renderizador Dinámico de Plantillas (`features/builder/TemplateRenderer.jsx`)

Archivo implementado en `src/features/builder/TemplateRenderer.jsx`:

```jsx
import React, { useEffect, useState } from 'react';
import { useParams, Link } from 'react-router-dom';
import { TEMPLATES_REGISTRY, getTemplateById } from '../../templates';
import { invitationsService } from '../../core/services/invitationsService';
import { Loader2, AlertCircle, ArrowLeft, Eye } from 'lucide-react';
import './TemplateRenderer.css';

/**
 * TemplateRenderer - Motor Renderizador de Plantillas Dinámicas
 * 
 * 1. Resuelve los datos de Firestore o vía prop directa en modo editor.
 * 2. Mapea el templateId con el registro dinámico (Elegante, Vintage, Moderna).
 * 3. Inyecta el JSON uniforme a los componentes interactivos (Countdown, Mapas, RSVP, Galería, Regalos).
 * 4. Gestiona estados de carga (Skeleton) y 404 (Not Found).
 */
export const TemplateRenderer = ({ 
  data: propData = null, 
  previewMode = false, 
  customTemplateId = null 
}) => {
  const { slug } = useParams();
  const [invitationData, setInvitationData] = useState(propData);
  const [loading, setLoading] = useState(!propData);
  const [error, setError] = useState(null);

  useEffect(() => {
    if (propData) {
      setInvitationData(propData);
      setLoading(false);
      return;
    }

    const fetchInvitation = async () => {
      try {
        setLoading(true);
        setError(null);
        const data = await invitationsService.getBySlug(slug);

        if (!data) {
          setError(`No encontramos ninguna invitación con el identificador: "${slug}"`);
        } else {
          setInvitationData(data);
        }
      } catch (err) {
        console.error('Error al cargar la invitación desde Firestore:', err);
        setError('Ocurrió un error al obtener la información de la invitación.');
      } finally {
        setLoading(false);
      }
    };

    if (slug) {
      fetchInvitation();
    }
  }, [slug, propData]);

  if (loading) {
    return (
      <div className="renderer-loading-state">
        <div className="loading-card">
          <Loader2 className="spinner-icon" size={42} />
          <h2>Preparando tu Invitación</h2>
          <p>Cargando detalles, itinerario y galería multimedia...</p>
        </div>
      </div>
    );
  }

  if (error || !invitationData) {
    return (
      <div className="renderer-error-state">
        <div className="error-card">
          <AlertCircle size={48} className="error-icon" />
          <h2>Invitación no encontrada</h2>
          <p>{error || 'Verifica que el enlace ingresado sea el correcto.'}</p>
          <div className="error-actions">
            <Link to="/catalogo" className="btn-back">
              <ArrowLeft size={16} />
              <span>Explorar Catálogo</span>
            </Link>
          </div>
        </div>
      </div>
    );
  }

  const activeTemplateId = customTemplateId || invitationData.templateId || 'elegante';
  const templateConfig = getTemplateById(activeTemplateId);
  const SelectedTemplateComponent = templateConfig.component;

  return (
    <div className="template-renderer-root">
      {previewMode && (
        <aside className="preview-top-banner">
          <div className="preview-banner-content">
            <div className="preview-badge">
              <Eye size={14} />
              <span>Modo Vista Previa</span>
            </div>
            <span className="preview-info">
              Plantilla activa: <strong>{templateConfig.name}</strong>
            </span>
          </div>
        </aside>
      )}

      <SelectedTemplateComponent data={invitationData} />
    </div>
  );
};

export default TemplateRenderer;
```

### Entregable 4: Estrategia de Enrutamiento en GitHub Pages

#### Causa del problema
GitHub Pages es un servidor web estático. Cuando un usuario accede directamente o recarga una URL profunda como:
`https://usuario.github.io/invitacion/invitacion/boda-juan-y-maria`
el servidor busca el archivo físico `boda-juan-y-maria.html` dentro de esa carpeta. Como dicho archivo no existe en el build, GitHub Pages retorna un error **404 Not Found** en lugar de delegar el enrutamiento al `index.html` de React Router.

#### Solución implementada (Estrategia SPA sin Hashes)
Se implementó la solución estándar de la industria (técnica `spa-github-pages`), la cual mantiene URLs limpias y compatibles con previsualizaciones de WhatsApp y redes sociales:

1. **`public/404.html` (Redirección inicial):**
   Al ocurrir el 404, GitHub Pages sirve `404.html`. Este script extrae la ruta completa solicitada (`/invitacion/boda-juan-y-maria`), la codifica como un parámetro de búsqueda (`/?/invitacion/boda-juan-y-maria`) y redirige instantáneamente a la raíz del sitio.

2. **`index.html` (Decodificación en `<head>`):**
   Antes de que React y React Router se monten en el DOM, un script en el `<head>` de `index.html` lee el parámetro `/?/`, decodifica la ruta original y ejecuta:
   ```javascript
   window.history.replaceState(null, null, decodedPath);
   ```
   Esto restaura la URL limpia en el historial del navegador sin provocar una recarga de página.

3. **Configuración de Vite y React Router:**
   - En `vite.config.js`: se define `base: process.env.VITE_BASE_PATH || './'` para que los assets (`/assets/*.js`, `/assets/*.css`) se resuelvan adecuadamente con rutas relativas o el subdirectorio del repositorio.
   - En `src/App.jsx`: se utiliza `<BrowserRouter basename={import.meta.env.BASE_URL}>`, garantizando que React Router interprete el prefijo del repositorio en GitHub Pages.

*(Nota: La alternativa con `HashRouter` (`/#/invitacion/boda-juan-y-maria`) no requiere `404.html`, pero genera URLs menos estéticas para una invitación de boda y afecta la metadata OpenGraph al compartir por mensajería).*
